# Backend Feature Matrix (Prompts 000–080)

Verified, source-derived inventory of what each backend prompt actually implements, for frontend planning.

**Method / how this was verified (do not trust names alone):**
- Spec files enumerated from `docs/*.md.txt` and `docs/0NN_*.md` (sorted).
- Service folders enumerated from `services/*`.
- Port = the `port: int = Field(default=NNNN, ...)` literal in each service's `app/config/settings.py`.
- Routes = every `@router.get/post/put/delete/patch(...)` path in each service's `app/api/*.py`, combined with that file's `APIRouter(prefix=...)` if one is declared (some services put the full path directly on the decorator instead of using a router prefix — both patterns were checked). Path parameters normalized to `{id}`. `health.py` (`/health`, `/liveness`, `/readiness`) excluded from the route list for brevity except where it's the *only* route surface (gateway).
- Capability = paraphrase of each service's own `README.md`, trimmed for length — not invented from the service name.
- Dockerfile / Tests = literal presence of `Dockerfile` and count of `tests/**/test_*.py` files in that folder.
- Where nothing could be verified, the cell says `UNKNOWN — VERIFY` rather than a guess.

**Notes on structure:**
- No `docs/000_*` file exists — spec numbering starts at `001`. Row 000 below reflects that.
- Prompts 001–010 are planning/architecture documents with no corresponding code (they *specify* how later services must be built).
- Prompt 011 maps to `services/gateway` — a deliberately minimal foundation-phase stub (health/OpenAPI only), distinct from `services/api-gateway-service` (prompt 056, the real API gateway the frontend actually talks to — see `architecture/authentication.md`).
- Prompts 012–029 ("Enterprise \* Framework") are not services — they are modules inside the single shared library `packages/shared-core/src/shared_core/`, imported by every business service. They have no port, no REST routes, and no Dockerfile (not independently deployed), but each has a matching `test_*.py` file confirmed under `packages/shared-core/tests/unit/`.
- Prompts 030–080 map 1:1 to `services/<name>-service` (or `-framework`/`-platform`) folders by name; all 51 exist and all were verified directly.
- `services/cloud-management-service` (prompt 068) is present in the working tree as an untracked addition (`git status`: `?? services/cloud-management-service/`) but is structurally complete — port, routes, Dockerfile, and 16 test files all verified present, same as any other service.
